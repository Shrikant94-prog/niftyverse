<a id="nv-18-01"></a>
## NV-18-01

**Outcome / scope:** Complete input-version/recipe snapshot manifests and dependency interval indexes. Retain filing document/taxonomy/mapping identities and resolvable fact-to-source/derived-input trace mappings.

**Requirements:** RES-03 STORE-02. **Dependencies:** Phase prerequisites above and the approved baseline.

### Acceptance

- **NV-18-01-AC1:** Snapshot manifests pin complete input versions, parser/schema/calendar/quality/recipe/environment identities and declared dependency intervals.
- **NV-18-01-AC2:** Different decision instants and policy/recipe versions cannot incorrectly share cached derived results; pinned dependencies survive cleanup.
- **NV-18-01-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.
- **NV-18-01-AC4:** Export layout is versioned independently of ingest partitions. Compare suitable date buckets and stable-ID/session sorting for long single-security and cross-sectional queries; record file/row-group counts, bytes scanned, memory and cold/warm latency. Repacking preserves logical selection and earlier snapshot references (AM-07).

- **NV-18-01-AC5:** Source and derived fact trace mappings retain exact locators, context/unit/period, revision/availability and parser/taxonomy/recipe identities; unknown metadata remains unknown (AM-17).

### Verification design

Build near-identical manifests differing in one dependency and assert identity/cache isolation. Attempt cleanup of a referenced input and verify retention protection. Benchmark both query shapes on identical logical data before/after repacking, avoiding per-symbol/day file proliferation and recording layout metadata.

## NV-18-02

**Outcome / scope:** Correction invalidation/recompute and readable snapshot diffs.

**Requirements:** RES-03 BUILD-02. **Dependencies:** `NV-18-01` plus applicable prerequisite contracts. Independent work may continue only under the phase dependency rule above.

### Acceptance

- **NV-18-02-AC1:** An accepted source/membership/calendar/action correction invalidates all affected descendants and only the declared unaffected outputs remain reusable.
- **NV-18-02-AC2:** Recursive EMA/RSI/MACD corrections propagate past nominal windows, match full recomputation and leave old snapshots intact with explained diffs.
- **NV-18-02-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.

### Verification design

Correct early inputs and compare incremental outputs against independent full rebuilds, including a far-future recursive value and unrelated partitions. Assert old snapshot hashes unchanged.

<a id="nv-18-03"></a>
## NV-18-03

**Outcome / scope:** Full offline replay from each declared capture boundary, Parquet/CSV round-trip, retention protection and verified restore; distinguish artifact integrity, logical recomputation and tested byte-identical regeneration. Replay structured documents with pinned offline parser/taxonomy artifacts; inspect direct bundles without claiming database history or absent raw-byte replay.

**Requirements:** STORE-02 RES-03. **Dependencies:** `NV-18-02` plus applicable prerequisite contracts. Independent work may continue only under the phase dependency rule above.

### Acceptance

- **NV-18-03-AC1:** Offline replay and Parquet/CSV round-trip preserve documented types, nulls, selected versions and logical results under pinned dependencies.
- **NV-18-03-AC2:** Backup→restore into a fresh location verifies facts/lineage/coverage/manifests; missing/corrupt dependencies fail explicitly, and artifact integrity/logical/byte-identical claims are separate.
- **NV-18-03-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.
- **NV-18-03-AC4:** Additive migrations retain old snapshot/config/view/type semantics; absent historical metadata stays unknown. New policy/recipe execution creates new outputs, while replay of an old policy either remains available or reports its missing pinned dependency (AM-08).

- **NV-18-03-AC5:** Structured-filing replay resolves only pinned local parser/taxonomy artifacts; direct bundles retain trace/coverage while raw omission reports replay unavailable and never invents a research snapshot (AM-14/AM-17).

### Verification design

Disable network and SDK imports as applicable; exercise corrupt files, absent parsers, disk exhaustion and two pinned reader processes during publication. Interrupt a new snapshot before its completion manifest and confirm it is undiscoverable while the old snapshot stays readable. Restore pre-migration fixtures with absent optional metadata and compare old selections/views; record platform/durability scope and exact comparison tolerances.
