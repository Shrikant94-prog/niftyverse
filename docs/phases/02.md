## Bounded discovery and completion

This goal completes a bounded investigation and initial capability/partition contracts, not universal source availability. Start with representative current/historical samples for each named family, using finite request/deadline budgets. A blocked response records evidence, impact, and next action; it does not trigger unlimited retries or new access techniques. Read [additional candidate leads](../CANDIDATE_LEADS.md) only for the family under investigation.

A transparent unavailable result can satisfy the investigation criterion; it cannot satisfy a later supported-adapter criterion. Missing evidence blocks only the dependent family. Do not require a ten-/fifteen-year corpus before independent foundation work. Finite tested parser safety limits and concrete reference concepts are fixed before implementing that family.

## NV-02-01

**Outcome / scope:** Build a bounded evidence-capture workflow; independently probe representative JSON endpoints, session requirements, windows and failures.

**Requirements:** CORE-02 NET-02 EQ-01 CORP-01. **Dependencies:** Phase prerequisites above and the approved baseline.

### Acceptance

- **NV-02-01-AC1:** Representative official-source probes retain timestamp, request scope, source/schema identity and redacted outcome; response success is distinguished from usable complete facts.
- **NV-02-01-AC2:** The workflow bounds request count/window/bytes/time and records challenge, throttling, timeout or missing history without bypass or fabricated data.
- **NV-02-01-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.
- **NV-02-01-AC4:** Action/event and optional surveillance/band capabilities have explicit format, effective/publication precision and measured coverage status. Current ASM/GSM lists or band snapshots cannot certify historical intervals; unavailable optional enrichment adds no dependency to price-only requests (AM-01).

### Verification design

Run a small explicitly scoped probe set plus deterministic capture/error tests. Include action/event catalogs and candidate JSON/CSV/ZIP surveillance/band sources, recording unavailable history without adding HTML/PDF parsing. Verify secrets are redacted and failed evidence stays failed; this adds no R1 permission gate.
