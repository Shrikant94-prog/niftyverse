Reject nonfinite, out-of-range, and inexact decimals before opening a sink; mixed valid/invalid batches must not alter pre-existing destination rows/schema/bytes. Validated data cannot be mutated after validation to bypass that contract. Scope these to the thin slice; full crash publication remains Phase 04.

Record frozen versus unconstrained installs separately and actually exercise every claimed optional extra. Network denial evidence must cover the tested subprocess boundary, and default tests must exclude live probes. For NV-01-03, explicitly select dumb/plain and capable-terminal conditions. Fresh implementation needs fresh visual evidence; do not inherit old approvals.

### Acceptance

- **NV-01-02-AC1:** An owned fixture containing valid/null/decimal/date values traverses msgspec → Arrow → real temporary DuckDB → Polars with the expected schema and values.
- **NV-01-02-AC2:** Invalid required fields fail with context before publication; fixture-provider orchestration needs no legacy imports or network access.
- **NV-01-02-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.

### Verification design

Use a hand-authored expected table and reject-network test fixture. Assert the persisted and returned values/dtypes, including null versus zero; prove malformed input is not published.
