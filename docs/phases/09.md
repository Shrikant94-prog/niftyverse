## NV-09-01

**Outcome / scope:** Python/TOML normalization, local explain/compiler, deterministic DAG, scope-aware partition reuse and resource budgets; freeze the ResearchPlan dependency-preflight/acquisition interface for warmup, prior filings and history bundles. Compile store-required builds versus direct extraction and source-format/output policies explicitly.

**Requirements:** BUILD-01 CORE-02. **Dependencies:** Phase prerequisites above and the approved baseline.

### Acceptance

- **NV-09-01-AC1:** Equivalent Python/TOML inputs normalize to the same deterministic work graph; explain/preflight performs no acquisition and shows missing warmup/prior-filing/history inputs.
- **NV-09-01-AC2:** Partition reuse respects requested universe, fields, basis, parser and policy; a subset or resolved snapshot cannot satisfy a larger history bundle.
- **NV-09-01-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.

- **NV-09-01-AC4:** Python/TOML source-format/output policies compile equivalently; missing store fails persistent build preflight while direct extraction needs none. Explain remains local (AM-17).

### Verification design

Compare equivalent configs and mutated field/scope/basis requests using known cache entries; assert graph nodes/reuse decisions and zero network calls during explain.

<a id="nv-09-02"></a>
## NV-09-02

**Outcome / scope:** Bounded executor, work/coverage checkpoints, required/optional statuses and unified events. Route the same validated batches to DB, bounded memory or direct file sinks; completion events follow each sink publication boundary.

**Requirements:** BUILD-01 BUILD-02 UX-01. **Dependencies:** `NV-09-01` plus applicable prerequisite contracts. Independent work may continue only under the phase dependency rule above.

### Acceptance

- **NV-09-02-AC1:** Executor concurrency/queues remain bounded and only committed validated partitions advance coverage and progress counts.
- **NV-09-02-AC2:** Required failure blocks dependants while independent work and optional dataset status follow explicit rules; poisoned data does not stop unrelated valid partitions.
- **NV-09-02-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.

- **NV-09-02-AC4:** Memory/file/DB sinks share normalization and validation; progress follows the selected sink publication boundary and explicit partial output never reports complete coverage (AM-17).

### Verification design

Use a multi-dataset synthetic DAG with delayed/failing tasks and a real store. Assert event order, resource limits, dependency states and fact/coverage consistency.

## NV-09-03

**Outcome / scope:** Resume, refresh overlap, explicit repair/reconciliation and offline acquisition behavior. Keep durable cross-run resume scoped to persistent builds; direct extraction reports bounded retry/partial-output limits.

**Requirements:** BUILD-02. **Dependencies:** `NV-09-02` plus applicable prerequisite contracts. Independent work may continue only under the phase dependency rule above.

### Acceptance

- **NV-09-03-AC1:** Build → cancel → resume → unchanged rerun preserves committed facts and adds no duplicate business rows; incompatible checkpoints fail with a clear reason.
- **NV-09-03-AC2:** Refresh/repair use declared overlap and completeness evidence; failed/mutating pages and offline missing inputs never yield complete coverage.
- **NV-09-03-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.

- **NV-09-03-AC4:** Direct mode reports bounded re-extraction/retry without a fabricated durable resume ID; persistent cancellation/resume guarantees remain unchanged (AM-17).

### Verification design

Interrupt at fetch/validation/commit boundaries, reopen the store and rerun. Check scoped hashes/counts and refresh supersession, including missing-cache offline behavior.
