<a id="nv-19-01"></a>
## NV-19-01

**Outcome / scope:** Finish immutable fluent selectors, async/sync boundaries and typed result methods using the existing compiler. Expose local instrument search, ETF selectors, statement views and EOD aggregation using existing contracts.

**Requirements:** API-01 CORE-01. **Dependencies:** Phase prerequisites above and the approved baseline.

### Acceptance

- **NV-19-01-AC1:** Fluent selectors are immutable, typed and equivalent to the existing compiler contract; chaining does no I/O until explicit execution.
- **NV-19-01-AC2:** Sync/async boundaries fail clearly in unsupported contexts without hidden nested event loops or divergent validation.
- **NV-19-01-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.
- **NV-19-01-AC4:** Standalone and ResearchPlan calculations use the same registered pure recipe/version. Standalone inputs validate schema, units, order, duplicate keys, session grid and basis; missing provenance stays unknown. Persisted reuse uses input hashes and declared context, not dataframe object identity (AM-06).

- **NV-19-01-AC5:** Local instrument search, ETF selectors, four statement views and EOD aggregate methods reuse established contracts without acquisition during selection (AM-15/AM-16).

### Verification design

Run installed-wheel type examples and equivalent API/DataPlan requests, spy on I/O during chaining, and test normal async use plus invalid sync-in-loop use. Compare standalone/pipeline values and diagnostics on valid and malformed inputs; arbitrary dataframe/SQL transformations cannot manufacture verified provenance.

## NV-19-04

**Outcome / scope:** Expose direct memory/CSV/Parquet extraction, offline local filing parsing and deterministic fact tracing; verify parity with persistent results and no hidden store/network creation.

**Requirements:** API-01 STORE-02 RES-03 CORE-02. **Dependencies:** `NV-19-03` plus phase prerequisites; use sequential internal checkpoints as needed; no separate execution-plan files.

### Acceptance

- **NV-19-04-AC1:** Direct Arrow/Polars/CSV/Parquet extraction and local filing parsing use the same validated facts/diagnostics as the persistent path; direct mode never creates/opens a DuckDB store and local parsing never fetches.
- **NV-19-04-AC2:** Fact tracing resolves retained source locators, original units/context/period and selected derived inputs. File manifests preserve schema/provenance/coverage and disclose missing raw bytes, partial output and absent durable resume/snapshot semantics.
- **NV-19-04-AC3:** Record observed acceptance evidence under [the common evidence rule](../WORKFLOW.md#definition-of-done) for the criteria and verification design below.

### Verification design

Run installed-package examples for a valid mapped local filing, unknown format, missing metadata/taxonomy, direct export and a derived fact. Compare canonical values/types/failures with DB output, spy on network/store creation, reload file manifests and assert trace behavior with/without retained raw bytes. Reuse Phase 04 sink-fault evidence unless changed; never claim it from a successful happy-path export.
