## Limits and completion boundary

Software verification is separate from source/dataset readiness. This phase
uses synthetic DAGs and explicit locally retained typed bundles, not new provider
probes. Existing source windows and membership verification remain bounded by
their evidence. CLI live-source parameter discovery is absent by design; Python
callers explicitly supply adapters through the provider protocol. Replay
validates retained typed facts and raw identity, not original-byte re-parsing.

The executor restarts incomplete atomic partitions rather than claiming durable
page-token continuation. Provider implementations enforce per-job transport/
format/body limits; Python offline spies/audit hooks are not a native firewall.
Code/config/input fingerprint compatibility, retained immutable inputs and the
existing publication durability protocol constrain replay. Power loss and
cross-platform byte regeneration are not certified. Future filing/Yahoo grids,
research feature formulas and their materialization invalidation remain later
phases; this phase propagates changes only through its actual acquisition DAG.

All required local outcomes and integrated cases pass; no human visual criterion
is required. Actual hosted results and final main/remote integration are recorded
in completion evidence after observation. Phase 12 is next eligible, not started.
