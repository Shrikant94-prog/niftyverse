## Storage and independently exercised boundaries

The price table layout is unchanged. Additive **v4** migration creates
`security_daily_details` for supplied trades, settlement/last/previous close,
delivery numerator/denominator/derived fraction/source percent/reasons, source
turnover units/representation/capture hash. Old v1-v3 migration definitions remain
version-correct; pre-upgrade v3 backups retain their version and owner marker.
Injected migration failure rolls back the new table/version while preserving old
data. Existing restore's accepted versions now include v4; v2/v3 remain supported.

`tests/test_equity_persistence.py` exercises actual new/old databases, transactional
rollback, retained pre-upgrade backup, exact DB/CSV/Parquet parity, capture mismatch,
forged derivations, incomplete source evidence and delivery-only output without
manufacturing prices. Exact derived fraction is decimal(38,12); source decimals
remain separate. Delivery-only source turnover **0.00015 INR lakh** is retained.
Competing-capture references stay in partition metadata; raw replay requires each
counterpart capture to be retained/published separately, not silently reattributed.

Real failing reproducers before repairs:

- Shared price batches initially accepted negative quantities/turnover/close.
  The first two reproducer attempts reached existing check/revision guards; the
  hypothesis was reassessed and isolated to batch construction. That test then
  failed with DID NOT RAISE before adding the shared numeric/OHLC validation.
  Both output formats now reject before a destination/catalogue change.
- The batch factory could wrap empty completeness evidence in nonempty JSON and
  appear complete. Its new failing reproducer now passes with an explicit proof
  requirement before metadata construction.
- A supported precise lakh amount was rounded by the default Decimal context.
  Source **1234567890123456789012345.12345678** now converts exactly to
  **123456789012345678901234512345.678 INR** using a bounded explicit context.
  A separate failing overflow case now yields numeric_precision before Arrow;
  canonical decimal(38,8) bounds are enforced without silent rounding.

No assertions or source/acceptance rules were weakened. The restore-version
regressions were ordinary affected-caller repairs, not unrelated refactoring.
