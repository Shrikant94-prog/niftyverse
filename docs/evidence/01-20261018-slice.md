## Contract and repair evidence

Fixture schema is deliberately local to Phase 01, not a selected NSE data
dictionary. Canonical ordering is `(session_date, instrument_id)`. One owned
JSON input is decoded and fully validated before either sink is touched.
Database output includes a separate fixture_provenance table. The pure core
knows no Arrow, SQL, networking or rendering. Only build_fixture lazily imports
the DB sink; extract_fixture imports no DuckDB storage module.

CSV encoding is UTF-8 with LF records and standard CSV quoting. Header order is
instrument_id, session_date, close, label. Every null cell is exactly `N`;
every value is `V` plus its text, including empty string (`V`), strings beginning
with N/V, and literal `__NULL__`. Dates are ISO; decimals have 4 places.
manifest.json records schema/version/encoding, original payload SHA-256,
capture/source kind, data.csv SHA-256, count and raw replay unavailable. Unknown
publication time remains null. No source financial semantics are fabricated.

Tests were written/run before implementation and initially stopped on the
absent public build_fixture import (collection error, not a demonstrated red
boundary behavior). After implementation all 20 initial cases passed. Additional
unsorted-input regression was run before its repair and failed: database rows
were sorted while direct rows retained input order. Moving sorting into the
shared decoder fixed that demonstrated mismatch; the expanded 25-test suite
then passed. Local format/type issues were ordinary repairs.

Existing destinations fail by default. Direct output uses a temporary sibling
then renames a completed local bundle; no Phase 04 crash durability, concurrent
publication, history catalog, incremental resume or snapshot guarantee is
claimed. The fixture slice materializes its explicit input; it is not a
long-history streaming implementation. Socket spies are Python boundaries;
installed-wheel subprocess audit checks are separate packaging evidence.
