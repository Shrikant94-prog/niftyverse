# Phase 01 - verified CSV read, 18 October 2026

Historical observation from the owner-requested final Phase 01 review;
current execution status belongs in [STATE](../../STATE.md).

Review of `8cfaf13` / state-only `e16d036` found that
`read_fixture_bundle` hashed bytes from `Path.read_bytes()` but reopened the
path for CSV parsing. A replacement between those operations could return
different values while the original checksum still passed. This violates the
reader's schema/hash-validation contract and NV-01-02's exact-value proof.
This finding concerns consistency of an explicit read; Phase 04 crash durability
and concurrent publication remain outside Phase 01.

The new `test_bundle_reader_parses_the_bytes_it_verified` replaces the file after
the checksum input is captured, changing a known price from `1.0000` to `9.0000`.
Before the fix it failed, returning `9.0000`; the separate changed-checksum
negative control already passed. The same regression also checks CSV commas,
embedded CRLF, quotes and Unicode in a label against an independent literal.

The fix parses the captured UTF-8 bytes with `io.StringIO(..., newline="")`.
There is no second file read, schema/API/encoding change or additional I/O.
The reader returns the values corresponding to the verified capture even if
the path subsequently changes. Ordinary corruption still raises ValidationError.
